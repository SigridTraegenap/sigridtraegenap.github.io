Principal component analysis

Four measurements per flower, boiled down to two: what PCA does to the iris data, and why standardising the variables matters.

Suppose you have measured a lot of things about a lot of objects and want to look at the result. If you measured two things, you draw a scatter plot. If you measured four, as in the data set on this page, you cannot draw the plot anymore, and with recordings from hundreds of neurons the problem is far worse. Principal component analysis (PCA) is the standard way out. It finds the few directions in which the data actually vary and lets you look at those.

Everything on this page runs in your browser. Nothing needs installing, and the figure updates as soon as you change a setting.

The data and the method

The data are the iris measurements collected by Anderson and made famous by Fisher (1936), probably the most used data set in statistics: 150 flowers from three species, and for each flower the length and width of a sepal and of a petal, in centimetres. Nothing about the method is specific to flowers. You could replace the four measurements by the firing rates of four neurons and everything below would read the same.

Write the measurements as a matrix \(X\) with one row per flower and one column per measurement, and subtract the mean of each column so that the cloud of points is centred at the origin. The covariance matrix

\[C = \frac{1}{n} X^{\mathsf T} X\]

is a \(4 \times 4\) table whose diagonal holds the variance of each measurement and whose off-diagonal entries say how strongly two measurements vary together. PCA, which goes back to Pearson (1901) and Hotelling (1933), asks a simple question of this matrix: along which direction in the four-dimensional measurement space is the spread of the data largest? The answer is the eigenvector of \(C\) with the largest eigenvalue,

\[C\, e_k = \lambda_k e_k ,\]

and the eigenvalue \(\lambda_k\) is exactly the variance of the data along \(e_k\). The second principal component is the direction of largest spread among all directions perpendicular to the first, and so on. Because the eigenvalues add up to the total variance, the fraction \(\lambda_k / \sum_j \lambda_j\) tells you how much of the data’s variability each component accounts for. If the first two fractions are large, a plot along those two directions shows you most of what there is to see.

One detail matters more than it looks: whether you standardise. The measurements all happen to be in centimetres here, but petal length ranges over about six centimetres while sepal width ranges over barely two. Variance grows with the square of the range, so without any correction the first component is mostly petal length, simply because that number is the biggest. Dividing each column by its standard deviation puts all four measurements on an equal footing. Whether that is the right thing to do depends on the data. If the measurements have different units, you almost always want it.

symEig = A => {           // Jacobi eigenvalue iteration for a small symmetric matrix
  const n = A.length, a = A.map(r => r.slice()), v = Array.from({length: n}, (_, i) => Array.from({length: n}, (_, j) => +(i === j)));
  for (let sweep = 0; sweep < 60; sweep++) {
    let off = 0; for (let i = 0; i < n; i++) for (let j = i + 1; j < n; j++) off += a[i][j] ** 2;
    if (off < 1e-18) break;
    for (let p = 0; p < n; p++) for (let q = p + 1; q < n; q++) {
      if (Math.abs(a[p][q]) < 1e-15) continue;
      const th = (a[q][q] - a[p][p]) / (2 * a[p][q]), t = Math.sign(th || 1) / (Math.abs(th) + Math.sqrt(th * th + 1));
      const cs = 1 / Math.sqrt(t * t + 1), sn = t * cs;
      for (let k = 0; k < n; k++) { const akp = a[k][p], akq = a[k][q]; a[k][p] = cs * akp - sn * akq; a[k][q] = sn * akp + cs * akq; }
      for (let k = 0; k < n; k++) { const apk = a[p][k], aqk = a[q][k]; a[p][k] = cs * apk - sn * aqk; a[q][k] = sn * apk + cs * aqk; }
      for (let k = 0; k < n; k++) { const vkp = v[k][p], vkq = v[k][q]; v[k][p] = cs * vkp - sn * vkq; v[k][q] = sn * vkp + cs * vkq; }
    }
  }
  const order = [...Array(n).keys()].sort((i, j) => a[j][j] - a[i][i]);
  return {values: order.map(i => a[i][i]), vectors: order.map(i => { const col = v.map(r => r[i]); const big = col.reduce((b, x) => Math.abs(x) > Math.abs(b) ? x : b, 0); return big < 0 ? col.map(x => -x) : col; })};
}
pca = {
  const rows = irisRaw.rows, d = 4, n = rows.length;
  const mean = Array.from({length: d}, (_, j) => rows.reduce((s, r) => s + r[j], 0) / n);
  const sd = Array.from({length: d}, (_, j) => Math.sqrt(rows.reduce((s, r) => s + (r[j] - mean[j]) ** 2, 0) / n));
  const X = rows.map(r => Array.from({length: d}, (_, j) => (r[j] - mean[j]) / (pcStd ? sd[j] : 1)));
  const C = Array.from({length: d}, (_, i) => Array.from({length: d}, (_, j) => X.reduce((s, x) => s + x[i] * x[j], 0) / n));
  const {values, vectors} = symEig(C);
  const scores = X.map(x => vectors.map(e => e.reduce((s, ei, j) => s + ei * x[j], 0)));
  const total = values.reduce((s, l) => s + l, 0);
  return {X, C, values, vectors, scores, total, species: rows.map(r => r[4]), mean, sd};
}

Reading the figure

The large panel on the left is the scatter plot. Each dot is one flower, placed according to whatever you chose for the two axes. By default these are the first two principal components, so you are looking at the four-dimensional cloud from the angle that shows the most spread. Colour marks the species, blue for setosa, orange for versicolor and green for virginica. It is worth switching the colours off for a moment: the grey cloud is what PCA actually works with. The method never sees the species labels, and yet the three groups come out separated, because the differences between species are also the biggest source of variance in the data.

You can also put two of the original measurements on the axes. Then the plot is an ordinary scatter plot of those two columns, and on top of it the first two principal components are drawn as lines through the origin, PC 1 in red and PC 2 in purple. Each line is as long as two standard deviations of the data along it, so you see both where the component points and how much of the spread it captures. Note that the lines are projections of four-dimensional directions onto the two measurements you picked, so they need not look perpendicular.

The bars on the right show the share of the total variance that each component explains. With standardisation on, the first component accounts for roughly three quarters and the second for most of the rest, which is the justification for looking at only two of the four dimensions. Below the scatter plot is the table of loadings, the entries of each eigenvector. A loading says how much a given measurement contributes to a component. The first component has similar loadings on three of the four measurements with the same sign, so it is essentially “overall size of the flower”. The second is dominated by sepal width and separates flowers that are wide for their size from those that are narrow.

Things to try

Switch standardisation off and watch the loadings table. The first component is now almost entirely petal length, and the explained-variance share of PC 1 goes up, not because the structure got cleaner but because one variable with a large range now dominates. Then put petal length and sepal width on the two axes, with standardisation still off, and look at where the red line points.

Put the third and fourth components on the axes. There is almost nothing left to see, which is what a small eigenvalue means in practice: those directions are mostly measurement noise and natural variation within a species.

This page is based on the dimensionality-reduction exercise in Dayan and Abbott (2001). For how the same method is used on neural population recordings, where the “measurements” are the firing rates of many neurons, Cunningham and Yu (2014) is a good starting point.
